# Architecture decisions (SFsmiths repository)

The full design history (Parts 1–11, D-001…D-070) lives in the design workspace that produced this repository.
This file records the decisions that shape the code here and the ones made while building it. Add new entries at the top.

| ID | Date | Decision | Why | Consequence |
|---|---|---|---|---|
| D-071 | 2026-09-05 | Product name **SFsmiths**; npm package `sfsmiths`; binaries `sfsmiths`, `sfsmiths-human`, `sfsmiths-hook`, `sfsmiths-mcp-evidence`, `sfsmiths-mcp-ui`; home `~/.sfsmiths` | "SF" + "smiths": craftsmen who forge, test and temper — an AI team for Salesforce, not a generic bot; name checked for collisions | all paths/env vars `SFSMITHS_*` |
| D-072 | 2026-09-05 | Subagent `tools:` lists plain tool names; command/path restrictions are enforced by hooks + static `permissions.deny`, not by `Bash(pattern)` in frontmatter | Claude Code docs: `tools` is an allowlist of tool names (+ `Agent(a,b)` main-thread, `mcp__server__*`), not permission rules | least privilege = tool set in frontmatter + hooks for arguments |
| D-073 | 2026-09-05 | `.claude/rules/*.md` with `paths:` kept (documented) alongside skills; org-specific standards generated as `<prefix>-*` skills from `docs/org-map/CONVENTIONS.md` | rules load when matching files are read; skills inject fully into agents | two channels, one source |
| D-074 | 2026-09-05 | Plugin pinned via `git-subdir` + 40-char `sha` in `.claude-plugin/marketplace.json` (documented for git-subdir) | near-daily upstream releases must not change agent behaviour silently | bump procedure in `.claude-plugin/README.md` |
| D-075 | 2026-09-05 | Every non-qa/repro agent stage gets one retry with the gate report before escalation; qa: develop → plan → escalate; repro: 2 tries | partial results and fixable gate failures should not escalate immediately; loops must stay bounded | `bounceTarget` in `state-machine.ts` |
| D-076 | 2026-09-05 | Human stages (deploy_uat, deploy_prod, remediation) are marked done by the human's command — that mark is the approval; no second approval prompt | avoid double-asking; deploy marks come from human-only verbs | `decideHandoff` step 4 |
| D-077 | 2026-09-05 | Write-guard role exceptions: a0-cartographer → `docs/org-map/**`; a7-coach → `knowledge/lessons/PENDING/**` + `MEMORY-AUDIT-*.md`; a7 confirmations of approved lessons are files (`CONFIRM-<id>-<date>.md`) merged by the daily learn run | agents never edit approved lessons or docs outside their role | `mergeCoachConfirmations` |
| D-078 | 2026-09-05 | Policy hook judges Bash writes by the **write target** (redirect target, tee target, cp/mv destination; whole command for rm/sed -i/chmod/mkdir/node -e/python -c) | `cp templates/x work/T/` is a read of templates; `echo x > .claude/settings.json` is a write even though echo is read-only | `writeTargets()` |
| D-079 | 2026-09-05 | `.mcp.json` passes `SFSMITHS_PROJECT_DIR=${CLAUDE_PROJECT_DIR:-.}`; project root resolution trusts only absolute env paths, else walks up for `config/orgs.yaml` + `.claude/` | Claude Code fails to parse `.mcp.json` when a referenced env var is unset and has no default | `findProjectRoot` |
| D-080 | 2026-09-05 | UI = local editor over `config/*.yaml` + human decisions (approve/reject/hold/lessons); 127.0.0.1 only, per-start token in the URL fragment, Host/Origin/Sec-Fetch-Site checks, CSP, no CDN | the UI must never become a second source of truth or a network surface | `src/ui/server.ts` |
| D-081 | 2026-09-05 | Evidence MCP tools: `prod_soql`, `prod_row_count`, `prod_tooling`, `prod_describe` — all read-only, all logged; UI MCP verbs fenced to development hosts (derived Lightning/VF/site hosts included), Setup paths refused, no JS-eval verb | one road to production; browser fenced at the network layer | `src/mcp/*` |
| D-082 | 2026-09-05 | `/feedback` is handled by the UserPromptSubmit hook → approved lesson immediately (human authority) + facts + skills regenerated | human feedback is the highest-quality lesson source and must not be fabricable by agents | `promptRouter` |
| D-083 | 2026-09-05 | Alias-specific static deny rules in `.claude/settings.json` are regenerated by `sfsmiths-human sync` from `config/orgs.yaml` | static denies must follow the configured aliases, not the defaults | `syncSettingsDenies` |
| D-084 | 2026-09-05 | Independent review fixes: rejection re-runs the stage; `learn` is the coach's agent stage; support-agent flow (ui-request.md → a8-ui → resume specialist, same attempt); no reliance on `stop_hook_active`; policy judges write targets incl. `mv`/`git mv`/`git rm` sources; explicit `-o` required for `sf data query|apex run|deploy|retrieve`; data-guard exempts `deploy_metadata`, picks the freshest canary; agent `gate/gates` are advisory (`--persist` to record); comms-lint forbids any email in client drafts and non-allowlisted ones internally; maintenance agents allowed after a finished ticket; `.active-ticket` cleared on done | review found the rejection path unreachable and several dead/mis-scoped checks | tests 08-review-fixes + updated 03/07 |
| D-085 | 2026-09-06 | Tests run through `scripts/run-tests.mjs` (explicit file list) and the Claude-Code-layer structure checks live in `scripts/repo-checks.mjs`; both are part of `npm run verify` and CI | first CI run on GitHub failed twice over: Node 20 does not expand globs in `node --test "test/**/*.test.mjs"`, and the inline `node -e` hook-wiring check broke on shell quote escaping (it would also never run on Windows) | one command, same result on Node 20/22 and every OS; `npm run check:repo` |
| D-086 | 2026-09-06 | A development-only configuration is a supported first run: with `no_preprod` both `deploy_uat` and `qa_uat` are skipped; `prod_verify` without an evidence org records a skip (report + `validations/prod_verify.json { skipped }`) instead of failing every check and escalating | the recommended first run on a new machine is Dev sandbox + file tracker; the conductor must not wait for a preprod deploy that cannot exist | `sfsmiths-human verify KEY` re-runs the checks once an evidence org is added; the setup wizard accepts `none` to skip an optional org (Enter always kept the default, so "blank for none" was unreachable), keeps piped answers, and never blanks the e-mail allowlist; test 10-dev-only-config |
| D-087 | 2026-09-07 | Policy R7 denies every `sf` command whose explicit target is not a configured development alias — reads included, bare usernames included (`-o user@example.com`), other sandboxes included | a real keychain holds more than the three configured orgs (other sandboxes, an admin production login under an arbitrary alias); the old rule only denied known preprod/prod aliases and `*prod*` names, so `sf data query -o <admin username>` against production would have passed the hook and shown unmasked data | agents reach exactly one org by CLI: the development org, by alias; doctor #6 remains the belt to this brace |
| D-088 | 2026-09-07 | Machine-specific static denies: `sfsmiths-human sync` (and setup / org add / remove) writes a deny rule for every org in the AGENT keychain that is not a configured development org — by alias and by username, `-o`/`--target-org`, both spellings — into the gitignored `.claude/settings.local.json`; `.claude/settings.json` keeps the conventional `Production*`/`PartialUAT*` denies even when no such org is configured; doctor 9g checks coverage | the first real machine had six orgs in the keychain (other sandboxes, an admin production login as DevHub) and the first Dev-only config removed the only static production denies — the hook (D-087) covered it, but the static belt must exist too and must not carry personal aliases into git | R7 hook + settings.local.json + settings.json defaults; also: doctor 2e parses `sf plugins` short names (`flow 2.0.1`), the wizard strips a pasted `[…]` default from the e-mail patterns; test 11 |
| D-089 | 2026-09-07 | Two config layers with one file name: tracked defaults in `config/defaults/<name>.yaml`, the user's copies in `config/<name>.yaml` (gitignored, read first); `.claude/settings.json` is static and never rewritten — the configured-alias denies (D-083) join the keychain denies in the gitignored `.claude/settings.local.json`; tests build their project from `config/defaults/` only | after the first real `setup`, `npm run verify` failed on the configured machine (4 tests) because tests copied the working tree's personal config; committing personal config would also leak aliases, e-mails and the Jira URL into a public repo | `git status` stays clean after setup; a fresh clone runs on defaults; hardcode-lint scans `config/defaults/`; `config/README.md`; supersedes the settings.json part of D-083 |
| D-090 | 2026-09-07 | **Spike 5 settled**: the canary PASSes on `NO_SINGLE_MAIL_PERMISSION` as well as `NO_MASS_MAIL_PERMISSION` | first real sandbox run: with Deliverability = All email the probe was delivered (correctly FAIL); after switching to System email only the SingleEmailMessage failed with `NO_SINGLE_MAIL_PERMISSION: Single email is not enabled for your organization or profile.` — the parser only knew the mass-mail code and answered `unknown` (honest, but blocking) | `classifyCanaryResult` + test; docs updated; data-guard keeps requiring a fresh PASS |
| D-091 | 2026-09-07 | Plugin marketplace is added from the repository root (`/plugin marketplace add ./` — the directory that contains `.claude-plugin/marketplace.json`; local paths must start with `./`, a bare `.` is rejected by the CLI), and the three project MCP servers are pre-approved by name via `enabledMcpjsonServers` in `.claude/settings.json` | Spike 1 first contact: the docs said `./.claude-plugin`, which is the wrong level per the Claude Code marketplace docs; the first `claude` run showed a 3-server approval dialog that was easy to abandon | docs/SETUP §5, README, doctor 9c, `.claude-plugin/README.md` |
| D-092 | 2026-09-07 | The hook-latency benchmark runs against a throwaway project root; the UI canary card reads the real state shape (`result`/`at`) and marks a pass older than `canary_max_age_minutes` as stale | on the first configured machine the dashboard showed 30 denials in 7 days and conductor −300 points before any ticket existed — every `npm run verify` had appended the benchmark's denials to the real `.sfsmiths/events.jsonl`; the card also showed `canary: unknown` right after a PASS because it read a `status` field that never existed | benchmarks and tests never touch the project's event log; operators clear a polluted log once (`mv .sfsmiths/events.jsonl .sfsmiths/events.pre-run1.jsonl`) |
| D-093 | 2026-09-07 | A running agent stage is a failure only when the SubagentStop stage-gate has stamped `agent_ended_at` for that attempt; otherwise the handoff answers the new **WAIT_AGENT** action (bounded by `AGENT_WAIT_CAP` = 8, then the normal bounce ladder). The agent-gate hook **denies a background Agent spawn** in every spelling and each specialist declares `background: false`. `<task-notification>` is recognised as a system message, not human-pasted evidence. `/resume` **recovers** a failed agent stage by RE-RUNNING its gates: all pass → the stage is done, with no agent re-run | Run 1, first real ticket: the conductor spawned a1-intake with `run_in_background`, its turn ended immediately, the Stop hook blocked, `decideHandoff` read `status: running` as "the subagent ended without passing gates", bounced the stage, spawned a SECOND a1-intake in parallel (breaking "never two specialists at once") and escalated 40 s in — while both agents were still working. Both then PASSED contract-check with 21 evidence refs each, and the second overwrote the first's files. Three defects in one: a background spawn was possible, "running" was conflated with "dead", and good evidence could not be recovered from a false failure | `WAIT_AGENT` + `agent_ended_at` + `agent_waits` in the manifest and the `.state.json` sidecar (both optional → old manifests load); `markAgentEnded`/`clearAgentEnd`; `isBackgroundSpawn`; `isTaskNotification`; `recoverFinishedStage`; conductor.md foreground rule + WAIT_AGENT branch; stop-guard says whether the agent is still live; repo-checks enforces `background: false`; test 12 |
| D-094 | 2026-09-07 | The per-ticket **token** budget is judged on **fresh tokens** (input + output + cache_creation), recorded per run and on `manifest.budget.fresh_tokens`; the raw total is still recorded and shown separately. Default **prices** ship in `config/budgets.yaml → prices` (USD per 1M tokens, matched as a substring of the model id); `metrics/prices.json` still overrides them; doctor #16 warns when a model has no price | One Run 1 prior-art agent recorded 13,299,604 "tokens" — of which 12,593,461 were cache READS, a re-read of the same context on each of ~63 round trips at roughly a tenth of the input price. The 1.5M per-ticket budget was crossed 21× in a single stage and nothing parked, because the number being compared was not the number that costs money. Meanwhile `metrics/prices.json` was never shipped, so `estimateUsd` returned undefined, every run recorded `usd: 0`, and both USD budgets plus the whole cost dashboard were dead | `freshTokens`, `loadPrices`, `priceFor`; budget check falls back to the total for pre-D-094 manifests; UI shows fresh vs cache reads and names the price source; test 02 (three park cases + backward compatibility) and test 12 |
| D-095 | 2026-09-07 | **Reasoning effort is per-agent configuration**: `config/models.yaml → effort` (low/medium/high/xhigh/max/inherit, `fallback_effort`), synced into the `effort:` line of `.claude/agents/*.md` next to `model:` (`inherit` removes the line), editable in the UI Agents screen, passed to the conductor session by `start --effort`, and **recorded with every run** in `metrics/agent-runs.jsonl`. Doctor #15 reports the effective level and warns when `CLAUDE_CODE_EFFORT_LEVEL` is set | Effort was never configured at all, so all 12 agents inherited one session-level value — on the first real machine `~/.claude/settings.json → effortLevel: xhigh`, which meant the conductor (deliberately a router that must not deliberate) and a9-comms (two drafts) ran at the same level as a2-repro and a3-architect. Worse, that value is a personal machine setting: the same repo produced different behaviour and cost on two machines, effort was recorded nowhere, and the golden-ticket replay could not tell effort drift from model drift | `EFFORT_LEVELS`; `syncAgentModels` writes both keys and never touches the others; `effortForAgent` on every `AgentRun`; UI dropdown + env-override banner; repo-checks validates a present level; test 12. Defaults spend reasoning where the work is hard: conductor/a0/a0b/a9 low · a5/a7/a8 medium · a1/a4/a6 high · a2/a3 xhigh |
| D-059…D-070 | 2026-09-05 | (design) Claude Code only; conductor + subagents + hooks + deterministic toolkit; agent/human verb split; fast deny hooks + static denies; installed copy outside repo; daily learn with human-approved lessons; Hercules bounded; masking; budgets | see the design workspace Part 11 §23.2 | this repository |
